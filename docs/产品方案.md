# 「作息」产品方案

个人日程管理 + 久坐提醒，一个浏览器打开就能用的单页网站。

---

## 1. 定位

一句话：**一个月历装下你排到月底的计划，同时盯着你坐了多久。**

| 项 | 内容 |
| --- | --- |
| 产品名 | 作息 |
| 产品形态 | 单页网站，浏览器打开即用，无注册、无登录、无安装 |
| 目标用户 | 每天在电脑前连续工作 6 小时以上的人 |
| 核心任务 | ① 这个月要做什么 ② 该起来动一下了 |
| 使用时长 | 常年挂在浏览器里，一天里反复瞥一眼，偶尔操作 |
| 数据归属 | 存在浏览器本地，每人一份，互相不可见 |

产品不追求功能密度。它替代的是两样东西：贴在显示器上的便利贴，和手机里那个永远想不起来的站立提醒。

---

## 2. 设计原则

1. **打开就看到这个月**。第一屏直接是月历，没有任何欢迎页、导航栏、登录框。
2. **一次交互完成一件事**。新增事项＝点加号写一行；勾完成＝点一下圆圈；开始工作＝点一下按钮。
3. **久坐计时由用户自己控制**。点「开始工作」就计时，点「去休息」就停，点「结束」就收工。没有自动识别，也没有需要猜测的状态。
4. **本地优先**。断网也能完整使用，联网只为首次加载页面。
5. **一个页面装下全部**。设置以抽屉形式浮在主界面上层，不跳转。

## 4. 模块设计

### 4.1 月历

主视图是整月网格，5 列 4～6 行，只显示周一至周五。周六周日不出现在日历中，跨月补位日期也只补工作日。

| 操作 | 交互 |
| --- | --- |
| 新增 | 悬停日期格右上角出现「＋」，点击就地出现输入框，回车保存，输入框保留可继续加 |
| 选中 | 点日期格选中该天，右栏「当日事项」联动刷新 |
| 改期 | 按住格子里的事项拖到另一天，松手即改日期 |
| 切换月份 | 顶部 ‹ › 按钮；「今天」按钮回到当月并选中今天 |
| 跨月日期 | 上下月补位日期灰显，点击后自动切换到对应月份并选中 |

**格子容量**：每格最多显示 3 条事项，标题单行截断；超出时在末尾显示「还有 2 项」，点该格在右栏查看全部。

**时间标注**：事项可带时间。输入 `10:30 评审会` 会自动识别时间前缀，显示为 `10:30 评审会`，并按时间排序；不带时间的事项排在当天末尾。

**今天与选中**：今天用一圈强调色描边标记，填充色与其他日期一致；选中日期用浅灰底标记。两者可以同时出现在一格上。

### 4.2 当日事项

右栏面板，展示选中日期的完整列表。

- 标题只有日期，右侧一个「＋」。点「＋」在列表顶部出现一行空白输入框，回车保存并继续出现下一行空行，Esc 或点开别处收起。
- 点事项文字就地编辑，回车保存，Esc 放弃。
- 点左侧圆圈标记完成，已完成的自动排到列表末尾，不加分组标题。
- 悬停出现删除图标（触摸端左滑），删除后底部出现「已删除 · 撤销」提示条，持续 5 秒。
- 列表为空时留白，不放任何提示文案。

### 4.3 久坐计时

**一个主按钮加一个结束按钮，三个状态。**

| 状态 | 左侧标签 | 按钮 | 点击后 |
| --- | --- | --- | --- |
| 未开始 | 当前连续久坐 | 开始工作 | 开始计时，状态转为工作中 |
| 工作中 | 当前连续久坐 | 去休息 ／ 结束 | 去休息进入休息计时；结束结算本次并回到未开始 |
| 休息中 | 当前已休息 | 开始工作 ／ 结束 | 开始工作回到计时；结束结算本次并回到未开始 |

- 「结束」用于下班离开、午休、临时离开半天这类场景：把本次计时结算进今日数据，然后把状态归零。没有它，用户只能靠关闭页面来间接停止，数据口径就变得不可解释。
- 点「去休息」的瞬间，当前连续久坐立刻结算进今日数据并归零，同时整页被休息遮罩接管；回来点「开始工作」关闭遮罩，从零重新开始。休息多久没有阈值判定。
- 状态跨刷新保留，重新打开页面接着上次的状态继续；若上次停在休息中，遮罩直接出现。

**休息遮罩**：全屏，正中三行——「已休息」、计时的已休息时长、「开始工作」按钮。休息期间整页被盖住，不再盯着日程和时钟。

**计时口径是「页面开着、机器没睡的时间」。** 关闭标签页、合盖休眠、系统睡眠都不计入。页面每 30 秒写一次心跳，重新打开时把空档扣掉；页面没关但随着机器一起睡过去的，靠两个时钟的差值识别（见 7.2）。挂起超过 30 分钟直接结束当天计时并提示：

> 上次计时在 18:03 结束

### 4.4 提醒规则

只有一条规则：**连续久坐满固定间隔**（默认 45 分钟）。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 固定间隔 | 45 分钟 | 每一轮提醒之后重新计时 |
| 忽略后再提醒 | 20 分钟 | 只在第一次忽略后生效一次 |

**节奏**：工作 45 分钟 → 提醒 → 忽略 → 20 分钟后再次提醒 → 再忽略 → 下一次回到 45 分钟，此后一直按 45 分钟循环。取休息或重新开始工作时，节奏重置。

**过滤器**：午休静默（默认 12:00–13:30，可关）、提醒日（默认周一至周五）。休息中不提醒。

### 4.5 提醒的送达

两个通道依次尝试：

1. **页面内全屏遮罩**。主通道，页面在前台时使用。两个按钮：**去休息**、**20 分钟后再提醒**（第二次起显示为 45 分钟）。
2. **浏览器桌面通知**。页面在后台时使用，需用户主动授权，未授权则跳过。

遮罩标题直接写已坐时长：

> 你已经连续坐了 48 分钟

### 4.6 便签

一张便签，全部内容都写在这一张上。像纸上的便利贴，不是卡片列表。

- 整块便签铺满右侧下方，点任意位置即可输入，边写边存。
- 标题右侧一个圆形色点，点开是 6 色色板：米黄、浅绿、浅蓝、浅粉、浅紫、灰白。
- 没有新建、没有删除、没有置顶。要清空就自己把字删掉。

### 4.7 设置抽屉

从右侧滑出，覆盖主界面，不跳页。

- **久坐提醒**：固定间隔、忽略后再提醒、午休静默与时段（未勾选时时段置灰不可编辑）、提醒日、桌面通知。
- **数据**：载入示例数据、清空全部数据（二次确认，输入「清空」才执行）。

## 5. 多用户与数据隔离

### 5.1 隔离机制

数据全部存在浏览器的 `localStorage`，键名固定为 `zuoxi.state.v1`。同一浏览器同一域名共享一份，不同浏览器、不同设备、无痕窗口各自独立。服务端只托管静态文件，不接收、不存储任何用户数据。

| 场景 | 结果 |
| --- | --- |
| 同一台电脑的 Chrome 与 Safari | 两份互不影响的数据 |
| 同一浏览器的不同窗口 | 同一份数据，实时同步 |
| 无痕窗口 | 独立的一份，关闭即消失 |
| 换电脑、换手机 | 看不到原来的数据 |
| 清除浏览器数据 | 数据丢失 |

### 5.2 数据边界

以下五件事不做，并在设置页中写清楚：

- 不做账号登录。
- 不做多设备同步。
- 不做团队共享。
- 不做数据导出、导入与自动备份。换设备或清理浏览器数据后不可恢复。
- 不做服务端推送。页面关闭时不提醒。

## 6. 数据模型

单个 JSON 对象，整体读写。

```json
{
  "version": 1,
  "settings": {
    "sitting": {
      "intervalMinutes": 45,
      "snoozeMinutes": 20,
      "lunchBreak": { "enabled": true, "start": "12:00", "end": "13:30" },
      "workdays": [1, 2, 3, 4, 5],
      "desktopNotification": false
    }
  },
  "runtime": {
    "sitting": {
      "status": "working",
      "workingStartAt": "2026-10-23T01:10:00.000Z",
      "restStartAt": null,
      "lastSeenAt": "2026-10-23T03:52:00.000Z",
      "nextReminderAt": "2026-10-23T03:55:00.000Z",
      "ignoredCount": 0,
      "dayKey": "2026-10-23"
    }
  },
  "days": {
    "2026-10-23": {
      "items": [
        {
          "id": "9f2c1a",
          "title": "整理季度数据",
          "time": "10:30",
          "done": false,
          "createdAt": "2026-10-23T02:10:00.000Z",
          "updatedAt": "2026-10-23T02:10:00.000Z"
        }
      ],
      "sittingSeconds": 11520,
      "breakSeconds": 2880
    }
  },
  "note": {
    "content": "报销单还没交\n周五前把排期发出去",
    "color": "yellow",
    "updatedAt": "2026-10-23T02:00:00.000Z"
  },
  "meta": {
    "createdAt": "2026-10-23T01:00:00.000Z",
    "lastOpenedAt": "2026-10-23T09:12:00.000Z",
    "selectedDate": "2026-10-23"
  }
}
```

设计要点：

- **日期用本地 `YYYY-MM-DD` 字符串做键**，不做时区换算，跨天判定用本地时区，避免 UTC 偏移导致的日期错位。
- **`settings` 与 `runtime` 分开**。前者是用户配置，后者是机器状态，每次读取都按领域字段归一化，历史遗留字段自然丢弃。
- **每天一个节点**，日程与久坐统计放在一起，切日期只读一个节点；月历渲染遍历 `days` 的键即可。
- **清理只针对过去**：只删除 90 天前的 `days` 节点，未来的日程永久保留。
- 时间戳统一存 ISO 字符串，显示时转本地时区。

## 7. 关键算法

### 7.1 久坐状态机

三个状态，三条边，全部由按钮触发：

```
未开始  --开始工作-->  工作中  --去休息-->  休息中
                        ↑                    │
                        └──── 开始工作 ───────┘
工作中／休息中  --结束-->  未开始（本次结算进今日数据）
```

时长一律由时间戳差值计算，不靠定时器累加。后台标签页的定时器会被浏览器降频到每分钟一次，累加式计时会失真。

```
工作中：当前连续 = now - workingStartAt
休息中：已休息   = now - restStartAt
今日累计 = 当天已结算秒数 + 当前连续
```

点「去休息」时把当前连续结算进 `sittingSeconds`，再把 `workingStartAt` 置空，所以连续久坐立刻归零。点「开始工作」时把休息时长结算进 `breakSeconds`，`workingStartAt` 重置为当前时刻。休息多久没有阈值。

### 7.2 页面存活与机器挂起

两条路径覆盖「用户不在但页面还在」的两种情况。

**关页重开**：页面每 30 秒写一次 `lastSeenAt` 心跳。重新打开时，若空档超过 1 分钟，把这段从 `workingStartAt` 与 `nextReminderAt` 中扣掉；超过 30 分钟则直接结算到最后一跳并结束当天计时；空档超过 10 分钟时给一条提示。

**机器挂起**：页面没关，但随着合盖或系统睡眠一起停住，网页里没有任何事件会触发。用两个时钟的差值识别——`Date.now()` 跟系统时钟走，睡眠期间继续前进；`performance.now()` 是单调时钟，睡眠期间停住。每秒对比一次：

```
drift = (本次 wall 增量) - (本次 mono 增量)
drift ≥ 60 秒 → 机器挂起过 drift 这么长
```

后台标签页被节流、被冻结时两个时钟都照走，差值为零，不会误判。另有一条兜底：单次间隔超过 10 分钟时，按「超出 1 分钟的部分」当作挂起。

判定出的挂起时长照两种处理：不足 30 分钟把挂起前的那一段结算进今日数据，回到工作中时重新起算连续久坐，今日累计只增不减；满 30 分钟同样结算到挂起开始的那一刻，然后结束当天计时，提示「上次计时在 18:03 结束」。跨夜也走这条路径，不会把入睡到午夜算成久坐。

### 7.3 提醒节奏

不在规则引擎里推算「距上次提醒多久」，而是每次状态变化时直接写下一次提醒的时间点 `nextReminderAt`：

- 开始工作：`now + 固定间隔`
- 提醒弹出：`now + 固定间隔`
- 点「稍后提醒」：第一次忽略用 `now + 忽略间隔`，第二次起用 `now + 固定间隔`
- 去休息、结束、跨天：清空

判定只需比较 `now >= nextReminderAt`，并且遮罩已经打开时不重复触发。10 分钟内重复检查，误差不累积。

### 7.4 跨天处理

每分钟比对一次本地日期。日期变化时：结算当天久坐、写入 `days`、把状态重置为未开始、清空提醒时间点。

## 8. 技术方案

### 8.1 技术选型

纯静态站点，原生 JavaScript（ES Modules），无框架、无构建步骤、无第三方依赖。首屏体积约 60 KB。

### 8.2 文件结构

```
zuoxi/
  index.html
  styles.css
  js/
    store.js         # 状态读写、localStorage 持久化、订阅通知
    calendar.js      # 月历渲染、拖拽改期、月份切换
    daypanel.js      # 当日事项列表、新增与编辑
    sitting.js       # 久坐状态机、计时、提醒规则
    notes.js         # 单张便签
    settings.js      # 设置抽屉、示例数据
    ui.js            # 弹层、撤销条、确认框、提示条
    main.js          # 启动、模块装配、心跳与跨天检查
```

模块之间只通过 `store` 通信：模块修改数据 → `store.commit()` → 写入本地并通知订阅者 → 各模块按需重绘。

### 8.3 渲染策略

按模块局部重绘。计时显示单独走文本节点更新，每秒不触发任何 DOM 重建；便签、事项编辑框获得焦点期间不再被订阅回调覆盖。

### 8.4 发布

作为静态站点放在 `zuoxi/` 目录，通过 `.github/workflows/deploy-pages.yml` 自动发布到 GitHub Pages；推送 `main` 的 `zuoxi/` 变更后，站点自动更新。同时保留一份 WorkBuddy 应用托管链接。无需后端、无需数据库、无需环境变量。

## 10. 空状态与首次进入

1. 月历直接渲染当月，今天描边高亮，不需要任何前置操作。
2. 久坐卡片显示「开始工作」。
3. 当日事项列表留白，右上角一个「＋」。
4. 便签是一张空白便签，点进去就能写。
5. 设置 → 数据 → **载入示例数据**：填充当月 12 条事项、1 张便签、6 天久坐记录，用于演示与截图。

---

## 11. 明确不做

- 账号、登录、密码、第三方授权。
- 多设备同步、云端备份、团队共享。
- 自动识别在座状态，或用传感器推断用户行为。
- 任务优先级、标签、子任务、附件、重复日程。
- 周视图、日视图、甘特图。
- 多条便签、便签分组。
- 服务端推送、邮件提醒、短信提醒。
- 任何形式的用户数据上传。

## 12. 验收标准

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| 1 | 首次加载 2 秒内出现完整月历 | 4G 限速下打开，无空白等待 |
| 2 | 点加号能连续录入多条事项 | 回车后仍停留在输入状态 |
| 3 | 能给下个月的某一天提前添加事项 | 切到下月，加一条，切回当月再切回下月仍在 |
| 4 | 拖动事项到另一天后日期正确变更 | 刷新后仍在新日期 |
| 5 | 已完成事项排在列表末尾，无分组标题 | 勾选一条后观察位置 |
| 6 | 点「开始工作」后计时开始走动 | 手动验证 |
| 7 | 点「去休息」后标签变为「当前已休息」 | 手动验证 |
| 8 | 点「结束」后回到未开始，今日累计增加 | 手动验证 |
| 9 | 点「去休息」后连续久坐立刻归零，今日久坐增加 | 手动验证 |
| 10 | 休息 10 秒再点「开始工作」，从零开始计时 | 手动验证 |
| 11 | 关闭页面 15 分钟后重新打开，计时未把空档算入 | 对比时间戳 |
| 12 | 模拟挂起 10 分钟，计时减少 10 分钟且状态不变 | 用假时钟或改系统时间验证 |
| 13 | 模拟挂起 31 分钟，直接回到未开始并提示结束时间 | 用假时钟或改系统时间验证 |
| 14 | 连续工作满 45 分钟弹出提醒，按钮显示 20 分钟 | 手动验证 |
| 15 | 第一次忽略后再提醒的按钮显示 45 分钟 | 手动验证 |
| 16 | 午休时段内不弹提醒；关闭午休静默后时段输入置灰 | 手动验证 |
| 17 | 便签内容刷新后仍在，颜色切换生效 | 手动验证 |
| 18 | 两个不同浏览器各自独立，互不影响 | 双开验证 |
| 19 | 深色模式下所有文字可读，无白底残留 | 手动验证 |
| 20 | 窗口宽度 375px 时布局正常，无横向滚动 | 手机浏览器验证 |
